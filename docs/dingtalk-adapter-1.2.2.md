# 钉钉招聘适配修复（1.2.2）

后续发现：1.2.2 的下拉触发调整未解决真实菜单识别；最终根因与 1.2.3 修复见 [SD 浮层修复记录](sd-popup-fix-1.2.3.md)。

2026-09-29，根据用户提供的 1.2.1 调试记录与登录后页面 DOM 检查修复。目标域名 `app135149.dingtalkoxm.com`，页面具有 Moka SD 兼容的 `apply-block-*`、`apply-fields-*.multi-*`、`sd-Select-*` 结构。检查只读取控件结构，没有填写或提交在线简历。

## 原因与修改

1. 域名未包含在站点适配中：日志 `siteAdapter: null`，栏目与重复记录信息丢失。下拉组件虽然被识别，项目/获奖/语言仍落入错误栏目。现在 `dingtalkoxm.com` 及其子域启用同一套 Moka 结构适配，复用已有标题、年月分拆、条目边界和奖项别名规则。
2. 未识别的条目序号为 `0`，项目覆盖分组却把它当成有效序号，导致四个项目合成一组、统一绑定资料“项目经历 8”。现在只有正序号可作为边界；无序号时按项目名称分组，并不将前置日期并入上一项目。
3. 下拉填写点击外层容器，未点击实际 SD Select 输入表面。现在选择真正的输入表面聚焦并点击，保留弹层归属、唯一选项及正式显示值验证，等待异步展开，不重复点击导致菜单关闭。
4. 部分下拉被表单声明为 `string_info`，原先依赖标题白名单判断，漏掉手机区号和最近毕业专业。现在以 `sd-Select-container` 和 addon 的真实控件结构判断，不再作为普通文本直接写入。

## 验证

- 钉钉结构样例 5 个浏览器用例通过：域名/栏目、四条项目分别绑定资料 1/2/3/8、五条奖项的姓名与年月归属、区号/专业代理下拉，以及仅响应子输入框点击且延迟 450ms 的下拉。
- 既有控件浏览器回归 25 个用例通过。

复现：`node tests/serve-browser-fixtures.mjs`，打开 `/dingtalk` 和 `/`。模拟数据与公开 DOM 结构分开，不保存用户资料。
