# 下拉选择保留与 AI 开关（1.2.5）

用户反馈：选择当前下拉后，切换到下一下拉时，前一个内容消失。

代码检查确认原有选中值读取存在歧义：正式显示节点为空时回退到搜索 input.value，搜索文字可能被当成选中值。1.2.3 又将点击目标限定在外层 `sd-Select-common-item`，未保证点击到内部 Menu 的内容节点，也未验证失焦后的状态。真实菜单的内部 `sd-Menu-content-item` 结构已在前次页面检查中观察到，但没有在真实账号表单上执行选择提交。

本次修复：

- 将候选项定位保持在当前菜单的选项行，点击目标优先选该行内部的 `sd-Menu-content-item`；没有该子节点时兼容原有行点击。
- SD Select 只读取正式显示节点，不再将搜索 input.value 作为选择成功证据。
- 等待页面处理选项点击，执行真实 blur，再等待渲染并验证正式值稳定。失焦后撤销的值返回失败，不能标绿后继续串填。
- 合并 AI 默认关闭修复：只有设置中的 `enabled === true` 才进行自动 AI 识别/匹配；后台也检查保存的开关。旧配置未带开关时默认关闭，API 参数保留。设置页关闭 AI 时不自动获取模型列表，也不为保存关闭状态申请 API 权限。手动测试连接/刷新模型属于显式操作。

本地验证：新复刻用例在修复前 5 通过、3 失败；修复后 8 通过，包括内部 Menu 点击、搜索文字不算选中、连续两个下拉选中值保留、失焦撤销不报成功。通用控件 25 个浏览器用例通过；15 个 Node smoke 文件通过，其中 AI 测试确认默认、旧配置、关闭、消息携带覆盖参数时自动 AI 请求均为零，显式启用后才进入请求路径。

这些验证使用虚构资料、模拟事件模型，没有填写真实投递页。后端持久化和线上完整填写仍需使用方核对。出生日期独立只读日历不属于此次普通下拉修复。

升级：在原扩展卡片重新加载 OpenJobAutofill，再打开插件。内容脚本版本为 `1.2.5-sd-commit`。旧版已经错误填写或丢失的字段需要重新检查后填写，程序不会自动恢复历史值。
