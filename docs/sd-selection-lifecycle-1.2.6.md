# SD 下拉生命周期修正（1.2.6）

用户反馈 1.2.5 中学历、专业等普通下拉仍在切换字段后清空。新日志的 AI 状态是 idle、results 为空、finishedAt 为空：不能据此判断哪一步清除了选中值。旧版定点“填入”也没有更新执行日志，空结果不一定意味着用户没有执行填写。

本次修正已确认的代码风险：

- SD 搜索此前复用了普通文本 setter，额外发送 change、blur，并写入 value 属性。现在仅更新搜索输入值并发送 input。
- 点击选项后原来只等待一次任务让出就强制失焦。现在先有界等待显示值匹配，再真实失焦并验证稳定状态，避免取消尚未完成的异步提交。
- SD 成功后不再发送 Escape；失败也不再用普通文本 setter 恢复搜索字串。搜索缓冲由控件的真实失焦处理。
- 批量完成后检查先前成功的 SD 控件是否仍匹配。发生回退时标记待处理，不擅自反复重填可能联动的字段。
- 导出日志会包含已经完成的字段；定点“填入”也会记录结果。SD 记录 opened、searched、clicked、settled、verified、cleanup 阶段的布尔状态，不记录选项文本、搜索内容或个人资料值；后台严格白名单过滤。

验证：新增搜索失焦和延迟提交用例在 1.2.5 下均失败，修正后通过。另覆盖后一个字段使前一个回退时的批量结果纠正。所有本地用例均为模拟控件，不等价于真实站点已验证；尚需在用户页面上确认残留问题是否消失。没有填写或提交真实投递表单。

更新方式：在浏览器扩展管理页重新加载扩展，然后在保留必要未保存内容后刷新投递页。调试日志版本应为 `1.2.6-sd-lifecycle`。若仍回退，导出执行后的日志；阶段状态用于区分点击未生效、失焦回退和后续字段联动。
