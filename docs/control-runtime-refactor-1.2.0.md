# OpenJobAutofill 1.2.0 控件与性能重构

本次保留现有资料格式、权限和 Moka 经历边界逻辑，借鉴 ResumeFiller 的“字段主标签优先于上下文”和“选定网页字段后定点填写”交互。适配器仍负责网站控件特有行为，公共等待、弹层归属和节点重取放入独立的 `src/form-runtime.js`。许可和参考快照记录在 `THIRD_PARTY_NOTICES.md`。

## 控件执行

`popup.js` 依次注入 `form-runtime.js` 与 `content.js`，同版本重复注入直接返回。`CONTROL_ADAPTERS` 的可选 `fill` 方法统一连接 Phoenix 日期、单选、下拉、Moka SD 下拉与飞书日期周期；原有 Layui 和 HotJob 专用实现继续工作。

下拉操作通过 `createChoiceSession` 获取当前控件的弹层。查找顺序为关联的 `aria-controls` / `aria-owns`、控件内部弹层、操作后新出现的唯一弹层。已有无关弹层不参与选项匹配，多弹层无法确定归属时返回失败。匹配限定在当前弹层，要求精确且唯一，并排除禁用选项及其子节点。

等待结合短期 MutationObserver 与低频兜底轮询；完成、超时、取消或读取异常均清理资源。异步搜索只用于寻找选项，必须点击正式选项并确认显示值与关闭/选中状态。支持最多 8 次的局部虚拟列表滚动。级联选择必须完成所有路径段；地区路径支持连续中文或斜线分隔。

框架替换节点后，通过原父级范围内的字段标记、ID、name 重新定位；不存在唯一稳定标识时保守失败。原生 select 同样要求唯一且可选，不再使用模糊包含匹配。普通文本写入检查完整内容，不以截断的预览值判断成功。未知选择控件不以写入搜索框作为成功兜底。

资料面板新增“填入”：先点击网页字段，再点对应资料的“填入”。自动填写与定点填写使用同一套适配器和执行锁，不需要增加资料副本。

## 资源与交互

- 单次扫描使用 WeakMap 缓存控件、字段容器和经历上下文；DOM 子树变化时失效，扫描结束释放。大表单按约 12 ms 的处理片段让出主线程，填写每 8 项让出一次。
- 资料分类和匹配条目按资料对象缓存，资料更新时重建。
- 进度只更新进度节点，不重建资料列表或丢弃正在编辑的输入；列表在分类、搜索或资料改变时更新。搜索使用 100 ms 防抖。
- 页面隐藏，或浮层已关闭且资料面板不可见/收起时，停止进度计时器。替换脚本时清理计时器、事件监听与运行中的控件等待。
- 面板出现与按钮交互使用短暂的 opacity / transform 动画；进度条改为 transform 过渡，遵循 `prefers-reduced-motion`。较长资料卡使用 `content-visibility`。同时隔离页面的输入框/按钮外边距，修正面板高度与窄屏溢出。

## 验证

Node 回归包含原有 Moka、Zhiye/Phoenix、HotJob、飞书、经历配对、日期与语义测试，新增等待生命周期测试，共 13 个测试文件通过：

```sh
node --test tests/*-smoke.mjs
```

真实浏览器使用实际 content/runtime 脚本、虚构资料和模拟扩展通信。在本地执行：

```sh
node tests/serve-browser-fixtures.mjs
```

打开 `http://127.0.0.1:4178/`。测试页自动执行控件场景，显示每项结果和资源计数。服务器只提供白名单内的测试页、脚本与字体，不提供整个项目目录或本机资料。

已通过 25 个真实 DOM 场景：长文本、只读、原生 select、Phoenix 主标签/下拉、Moka SD 与学历等价写法、异步搜索、重复与禁用选项、弹层隔离、框架重建、级联成功与缺失末级、虚拟列表、未知控件失败、定点填写、编辑取消、进度列表稳定性，以及 180 字段扫描分片。所有控件场景结束后活动等待和观察器均为 0。

2026-09-28 在同一浏览器中对比修改前 1.1.31 工作区快照与当前版本；180 个字段、30 组经历，预热一次后取三次扫描中位数：

| 指标 | 修改前 | 1.2.0 |
| --- | ---: | ---: |
| 扫描耗时 | 641 ms | 410 ms |
| querySelectorAll 次数 | 5,764 | 1,540 |
| cloneNode 次数 | 2,700 | 212 |
| 30 次进度更新耗时 | 37 ms | 1 ms |
| 进度更新引起的资料列表 DOM 变更记录 | 93 | 0 |
| 资料列表节点保持不变 | 否 | 是 |

扫描样本分别为 662/584/641 ms 和 537/410/378 ms。新版扫描耗时约减少 36%，深克隆约减少 92%。这是合成 DOM 的相对结果，没有测量浏览器进程 RSS，也不代表所有真实招聘页的提升幅度。

可选性能对比：保留修改前的 `content.js` 文件，用以下命令启动，再打开 `/benchmark`：

```sh
node tests/serve-browser-fixtures.mjs --baseline=/absolute/path/to/old-content.js
```

## 验证边界

- 本轮没有拿到新的具体 Zhiye 招聘表单样本，未在真实在线申请中写入或提交。浏览器测试模拟了组件 DOM 与状态变化，没有加载各家前端框架的完整发行包。
- Phoenix 日期/地区确认和飞书日期的已有专项测试继续通过；它们保留各自的专用导航逻辑。新运行层不等于所有日期、树、多选、iframe 或闭合 Shadow DOM 已全面支持。
- 超过等待时限的远程加载、无法唯一定位的弹层或节点、仅显示末级但无完整路径证据的级联、未覆盖的虚拟列表，应进入待处理，不能报告已完成。
- 无新运行依赖、无浏览器权限扩张。扩展管理页重新加载后使用 1.2.0；刷新招聘页前先保存网站中的内容。
